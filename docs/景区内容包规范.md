# 景区内容包 v1

一个景区一个包，包内结构统一，引擎与工具共享。此规范同时供开发者和 Agent 使用，不依赖编辑器或 Agent 平台。

## 目录与所有权

```text
scenics/
  catalog.json                  # 景区顺序、默认景区、首页展示景点
  westlake/
    manifest.json               # 景区信息、地图入口、景点顺序、内置种子策略
    assets.json                 # 景区共用资产的文件/URL/哈希/发布清单
    map/
      manifest.json             # 地图包版本、关联层、可用风格
      geography.json            # 地理、路网、景点坐标
      layout.json               # 模型布置与共享环境
      interaction.json          # 相机、移动、导览与集章
    assets/                     # 景区绘卷、概念参考等
    spots/
      huagang/
        spot.json               # 景点文案、2D 图钉、照片引用、世界模型配方
        assets.json             # 该景点资产、来源/许可、压缩配方、发布策略
        photos/                 # 实拍原件
        generated/              # AI 补图原件
        worlds/                 # SPZ、不可变生成凭据、全景和输入副本
        web/                    # 按配方生成并入库的网页副本
    docs/                       # 设计、提示词、验收与人工审核记录
    provenance/                 # 不可变的历史来源快照
    tools/                      # 只适用于该景区的来源整理/路网制作脚本
  forbidden-city/               # 遵守同一份规范
```

目录按需要创建。没有生成世界的景点不需要空的 `worlds/`，也不能复制其他景点的世界模型冒充成果。新景区的地图、介绍、图片、许可、补图和世界模型都归属自己的包。

通用渲染器和建筑模型仍在 `src/map3d/`，通用风格仍在 `src/map3d/styles/`；维护端、游客端、导航与世界查看器仍是共用代码。跨景点路网归属景区地图，不拆成多份景点路网。独有建筑的实例参数进入 `layout.json`，可复用的造型能力进入共用模型库。

## 文件契约

- `scenics/catalog.json` 只注册景区 ID 和展示顺序。`npm run sync:scenics` 自动生成 `src/content/generated-catalog.js`，不要手写这个文件或在渲染器另建注册表。
- 景区 `manifest.json` 使用内容包 `schemaVersion: 1`。其中 `map.package` 固定为 `map/manifest.json`，`map.asset` 引用景区级 `assets.json`，`spots` 是按展示顺序排列的景点目录名。它与地图包的 v1/v2 是不同的版本体系。
- `spot.json` 的 `id` 必须等于目录名，并出现在地图 `geography.spots` 中；`photos`、`publishedPhotos` 的值是本景点资产 ID，不是其他景区的路径。`publishedPhotos` 只用于内置的已审核展示样例，后续发布仍由维护端执行。
- `assets.json` 的每条记录有 `id / file / url / sha256 / publish`。`file` 相对当前资产清单所在目录；不得含 `..`、绝对路径或符号链接。URL 在全仓库唯一。照片的 `photo` 保存 `name / kind / credit`，许可、来源、作者和修改说明随照片一起维护。
- `delivery` 可声明缩放压缩副本，包含 `file / url / sha256 / maxDimension / quality / changes`。`publish: false` 表示原文件不进入网站；存在 `delivery` 时副本仍会发布。世界生成 API 读取的是包内原图，不拿压缩图替代原图。
- `spot.sample` 可配置经过核验的补图和世界样例；`reference` 精确绑定实拍、视角和资产 ID，`binding` 保留世界 ID 与输入 URL，`worlds` 引用本景点 SPZ/receipt。普通景点省略整个字段。补图保持 `ai-demo` 并经人工审核，不能标成实拍。
- Schema 位于 `schemas/scenic-*.schema.json`，与 `src/content/contract.js` 同源。新增字段需要同时修改契约、消费者和文档，运行 `node scripts/validate-scenics.mjs --write-schemas` 更新 Schema。

## 构建与兼容

`src/content/catalog.js` 统一装配初始内容、照片、样例和资产索引；地图注册表从同一个目录派生。`src/scenic-core.js` 不再知道某一景点的图片路径或 SPZ 文件名。

构建先同步注册表、校验内容包、校验地图，再根据资产清单复制所需文件到 `dist/`，最后打包应用。`public/` 只维护全站通用文件。不要手工把景区素材再复制进 `public/` 或修改生成的 `dist/`。

旧资源 URL 作为稳定标识保留，例如 `/assets/real/huagang.jpg` 现在映射到 `scenics/westlake/spots/huagang/photos/huagang.jpg`。因此原有浏览器草稿、发布快照、世界生成凭据和深链接仍能使用，工作区/景区 schema 无须因目录搬迁升级。新资产推荐 URL：`/assets/scenics/<scenic-id>/spots/<spot-id>/<filename>`。

历史生成凭据与原始图片保持字节不变；凭据中旧的仓库路径可通过 `scenics/migration-v1.json` 追溯。`provenance/` 中的旧汇总清单是历史快照，当前资产配置以每个所有者的 `assets.json` 为准。

`seedOnUpgrade: true` 表示把新内置景区补入旧工作区一次。已有景区内容不会被覆盖，用户删除过的内置景区不会反复恢复；用户上传、草稿和已发布内容始终保留。历史 schema 兼容逻辑集中在 `src/content/legacy-migrations.js`，新增景区无需修改它。

## Agent 制作与交付步骤

1. 确定景区 ID 与景点 ID，创建景区包。读取本规范、地图工作流、JSON Schema 和最接近的现有样例。
2. 整理地图四层、每个景点的 `spot.json`、实拍、来源、授权和图钉；没有实景世界时提供照片入口。
3. 将素材放入其所有者目录，记录 SHA-256、URL、发布策略；补图提示词、人工修改与验收记录放入包内 `docs/`。世界模型的原始凭据不随重构改写。
4. 需要网页副本时添加 `delivery` 配方，运行 `node scripts/prepare-web-images.mjs`（当前使用 macOS `sips`）。构建直接使用已入库副本，不要求部署机器具有 `sips`。
5. 在 `scenics/catalog.json` 加入新 ID，运行 `npm run sync:scenics`。新增普通景区无需修改 `scenic-core.js`、地图注册代码或构建排除列表。
6. 运行下列校验和构建。检查所有素材来源、引用、哈希，确认景点内容与地图一一对应。校验报告分别写入 `artifacts/scenic-validation.json` 和 `artifacts/map-validation-<id>.json`。
7. 浏览器检查总览/近景、全部风格、照片详情、世界入口和维护端，再由景区确认事实、许可及通行信息。代码推送与站点发布分别记录。

```sh
npm run sync:scenics
npm run check:scenics
node scripts/validate-map.mjs scenics/forbidden-city/map/manifest.json
npm test
npm run build
PORT=4177 npm run serve
```

`npm run dev` 会监听已注册 JSON 的编辑；新增目录、更改注册成员或替换图片后需重新启动，让资产复制及注册步骤重新执行。
