# 三维景区与景点制作指南

本指南供开发者及任意编码 Agent 使用，不需要安装特定平台的 Skill。命令从仓库根目录运行；先读 [地图数据包与 Agent 工作流](地图数据包与Agent工作流.md)，格式以 [schemas](../schemas) 和 [contract.js](../src/map3d/contract.js) 为准。

当前包含西湖 v1（五种风格）与故宫 v2（皇家微缩、积木宫城）。故宫增加实体障碍、门洞与中轴导览，见[故宫制作与验收](../scenics/forbidden-city/docs/故宫制作与验收.md)。新景区仍需资料整理、程序校验和人工审图，不能由任意一张图片保证准确三维化。

## 选择任务

| 要交付的内容 | 主要入口 | 需要同步的内容 |
| --- | --- | --- |
| 新景区大地图 | `scenics/<map-id>/` 与 `scenics/catalog.json` | 景区内容快照、景点 ID、地图包、来源与验收记录 |
| 已有景区的新景点 | `geography.json` 的 `spots`、`layout.json` 的 `landmarks` | 内容快照中的照片/讲解、停靠节点、2D 图钉和可选世界模型 |
| 新视觉风格 | `src/map3d/styles/`、`packages.js`、目标 manifest | 造型能力、Schema 和所有现有风格的兼容性 |
| 单景点实景世界 | 维护端照片/3D 标签、本机 `server.mjs` | 已审核输入照片、生成任务、SPZ、receipt、漫游范围与朝向 |

大地图由结构化地理数据和模型库渲染；单景点世界由照片生成 SPZ。两者分别制作、分别验收。

## 新增一个景区

1. **整理来源与范围。** 记录景区地图/地理数据、景点资料、图片许可、原点、单位、坐标轴和人工假设。只有一张插画地图时，不得直接把像素位置当经纬度。
2. **对齐景区和景点 ID。** 地图包的 `manifest.id` 必须与内容工作区里的景区 ID 一致；`geography.spots` 的键必须与内容中的景点 ID 一致。地图包 ID 遵循 Schema 的小写字母开头规则。维护端 `newScenic` 当前返回随机 ID，不要假定它一定符合地图包规则；衔接已有草稿时，需要明确映射或实现保留旧数据的迁移。
3. **准备内容快照。** 维护端可创建景区、上传地图和照片并发布到当前浏览器。若要让新访客在静态站点看到新景区，还需将审核后的内容纳入仓库的初始化数据，并处理已有工作区的增量迁移；入口是 `src/scenic-core.js` 的 `createWorkspace` / `upgradeWorkspace`。仅注册地图包不会创建游客内容卡片。不要覆盖用户上传、编辑过的内容或已发布快照。
4. **生成地图包。** 参考西湖的文件结构，建立 `manifest.json`、`geography.json`、`layout.json`、`interaction.json`。重新整理当地地理与路网，不复制西湖的湖岸、原点、景点坐标或采样脚本常量。通用编译器是 `src/map3d/geography.js`。
5. **布置模型。** 使用受控模型 ID，在 `layout.landmarks` 填写位置、旋转、尺度和 `spotId`。现有模型不足时先扩展模型库与契约；不要把未经支持的模型名或可执行代码塞进 JSON。
6. **注册与适配。** 在 `scenics/catalog.json` 注册景区，运行 `npm run sync:scenics` 生成统一入口；`geo-registry.js` 从注册表派生地理实例。复用或新增风格，并检查标题、时节、印章、来源署名等文案。目前部分界面和风格配置仍有西湖文案，新景区需要一并适配。
7. **验收目标包。** 默认 `npm run check:map` 和构建入口会遍历地图数据目录。新景区先显式执行下方目标包命令，再检查地图/详情/世界入口、桌面与窄屏、路线和风格切换。报告分别写入 `artifacts/map-validation-<map-id>.json`。
8. **交付。** 提交内容与地图包、来源、代码、验证结果和待人工核对项。站点发布按实际部署流程执行，浏览器里的发布按钮不等于云端部署。

将以下 `map-id` 替换为目标景区 ID：

```sh
node scripts/validate-map.mjs scenics/map-id/map/manifest.json
npm test
npm run build
npm start
```

当前契约与渲染仍以湖泊园林场景为基准，例如地图包要求水域数据。山岳、室内等不同类型景区如无法合理表达，应扩展契约和渲染能力，不能伪造水体来通过校验。

## 在已有景区新增景点

1. 在内容草稿中添加景点名称、资料、照片和 2D 图钉；使用稳定、与地图包一致的景点 ID。
2. 在 `geography.network.nodes` 新建或选取可走的停靠节点，必要时补充 `edges`。节点应在入口或可达区域，不要塞进模型内部。
3. 在 `geography.spots` 增加该 ID 的 `node`、`label`、`scene`、`season` 和可选 `heading`。运行时的 `SPOT_GEO` 由该数据派生，无需另写一份常量。
4. 在 `layout.landmarks` 增加唯一绑定该 `spotId` 的模型实例。修改 `layout.labels` 可以增加地名文字。通用渲染器读取这些实例，不再要求向 `scene.js` 添加坐标和 `tag()` 调用。
5. 校验目标地图包；在游客发布快照中检查卡片、自动步行/乘船、到达判定、集章和邻接路标。新增模型可能遮住道路，必须看近景并试走。
6. 需要实景世界时，另按下面的照片生成流程完成。没有已验证的 SPZ 和 receipt 时，景点提供照片入口，不要复制花港模型充当新景点。

维护端“添加景点”目前只创建内容数据，不会自动补齐上述地图包与模型实例。2D 图钉线性映射到三维只是未校准点位的回退，不是正式地理定位。

## 新增风格

参考 [地图数据包与 Agent 工作流](地图数据包与Agent工作流.md) 中的风格规范。新增 style JSON 后在 `src/map3d/packages.js` 注册，并加入目标 `manifest.styles`。造型策略在 `style-geometry.js`，显示高度在 `surface.js`；角色、道路和模型必须使用同一个显示高度。保留已审核的地理位置与可达关系，不为换风格重新排列景点。

## 单景点 3D 世界

### 实际链路

1. 工作室景点的「照片」页放图片。六个视角槽位是 `front` `left` `rear` `back` `top` `inside`，外加不限数量的 `more-…`。
2. 送去生成的只有 `front` `rear` `back` `left`（`scenic-core.js` 的 `WORLD_ANGLES`）。俯视和近景不参与，因为生成接口只按方位角摆照片。
3. `worldInputs`：实拍、景区上传，以及 `kind==='ai-demo'` 且 `accepted===true` 的补图。未审核的 AI 补图不会送出。
4. 工作室「3D」页选模型后 `POST /api/worlds`。本机 `server.mjs` 才有这个接口。静态站点没有，界面会提示需要本机服务。
5. 服务要求 `WORLDLABS_API_KEY`。密钥只留在本机环境，不进前端、不进 Git、不随静态网站打包。没有密钥时接口返回 503，不扣费。
6. 当前代码支持两个模型（名称与预计费用以 `src/scenic-core.js` 和服务配置为准，不代表供应商未来不会变化）：`marble-1.0-draft`（界面约 230–250 credits）、`marble-1.1`（约 1,580–1,600 credits）。一次 1–4 张、方位不能重复。
7. 方位写死：正面 0°、右侧 90°、背面 180°、左侧 270°。提示词要求保留照片里的建筑、材质、植被和日光，不要人和额外建筑。见 `server.mjs` 的 `text_prompt`。
8. 同一 `requestId` 重复提交会返回已有任务，避免点两次扣两次。上传阶段失败会删掉任务（上传不计费）。提交超时或 5xx 标成 `uncertain`，这时可能已经建了计费任务，先到 World Labs 核对，不要立刻重提。
9. 前端每 4 秒 `GET /api/worlds/<requestId>`。完成后服务下载 SPZ（优先 `500k`，否则 `full_res`，再否则 `100k`）。

### 成功后的文件槽位

目录在数据根的 `worlds/<worldId>/`（默认随本机服务的 data 目录，测试里是 `data/worlds`）：

- `world.spz`：场景本体
- `receipt.json`：模型、输入方位、`metric_scale_factor`、`ground_plane_offset`、起点 `view.home` / `view.target`、花费、文件 sha256

游客和预览通过本机服务读：

- `/generated/<worldId>/world.spz`
- `/generated/<worldId>/receipt.json`

静态站点构建不包含这两个文件，也没有 `/generated`。

草稿上的槽位是 `spot.world`（`applyGeneratedWorld`）：

```text
kind: 'generated'
model, worldId, spz, receipt, credits, inputs, createdAt
```

`worldAsset` 只认 `spz` 匹配 `/generated/<id>/world.spz` 的生成结果。别的 URL 会被忽略。

发布是整份草稿的拷贝（`publishScenic`）。`spot.world` 跟着发布快照走，但文件仍在本机 `worlds/`，不在 `dist/`。

照片换了之后，`worldStale` 用「方位=图片 url」对比。旧世界还在，工作室只提示可以重新生成。重新生成会再扣 credits。

### 花港是特例，不是新景点的空槽

只有景点 id 为 `huagang`、保留与内置试点一致的 `pilotAsset`，且正面仍为 `kind: real` 的 `/assets/real/huagang.jpg` 时，才回退到打包文件：

- 单图：`scenics/westlake/spots/huagang/worlds/huagang-500k.spz` 与 `huagang-generation.json`
- 六图试验：`huagang-multi-500k.spz` 与 `huagang-multi-generation.json`

六图试验是另一次生成（1 张实拍 + 5 张已审核 AI 补图），提示词和输入都不同，不是对照实验。AI 补出的背面和屋顶不代表实地。换掉或删掉花港正面实拍后，这个回退断开，不会自动套到别的景点。

### 播放

`pilot-world.js` 的 `mountPilotScene` 拉 receipt，用 `ground_plane_offset` 当眼高，`view.home` / `view.target` 当起点。`viewer.js` 只做范围受限的行走（WASD、拖动环顾）。范围来自 `spot.roam`，缺省是 `DEFAULT_ROAM`（前 2.5 m、后 0.6 m、左右 1.2 m、上 0.4 m、下 0.5 m），工作室滑块可改，发布后游客端用同一份。

单景点世界里的路标方向 = 大地图路网方位 − 该景点的 `heading`。`heading` 是起始视线的罗盘角（0 为正北，顺时针）。花港初始值 20 是看照片后的手估，不是测量值。工作室「制作助手 → 地图校准」可以改，并可用 `#pilot?...&heading=` 预览，采用后才写入草稿。

## 交接与证据

交接说明应包含：景区/景点 ID、输入资料与许可、修改文件、目标地图包校验结果、浏览器检查结果、模型生成记录、访问入口和仍需景区确认的事项。

- 事实、展示性处理与模型推测分别标明。AI 补图经过审核也不等于实拍。
- 自动校验验证结构、引用和空间关系，不能替代现场核对与人工审图。
- 本机任务、浏览器草稿、仓库内置资产和线上站点分别报告，不把一种状态当成另一种已经完成。
- 不把规划中的云端同步、独立 Agent 服务或外部行程平台接入写成已完成。
