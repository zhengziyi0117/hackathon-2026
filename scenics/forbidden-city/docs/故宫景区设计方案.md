# 故宫景区设计方案

设计日期：2026-10-14。状态：原始设计方案；首版实施与验证见[故宫制作与验收](故宫制作与验收.md)。基于代码 `7c98867` 与故宫博物院公开资料。

## 体验定位

把故宫做成一座可以走进去探索的皇家微缩沙盘：从全景辨认中轴与宫城，跟随小人穿过院落，在重要建筑前停下听讲解、看实景、收集印章。保留现有网站的布局、字体、卡片与操作习惯。

首版主风格为“皇家微缩”，主色是朱红、琉璃金、暖白石和低饱和青绿。用建筑形制、院落秩序与光影体现精细度；地图中的主要建筑要能凭轮廓认出。

这也是地图工作流的第二个案例：通过故宫验证同一套数据契约和渲染框架能否覆盖建筑密集型景区。

## 第一眼与视觉规范

- 初始镜头位于南侧上空，朝北看完整宫城；中轴线从近处午门延伸至远处神武门。缓慢落到可操作的斜俯视角，直接显示“自由探索”和“沿中轴游览”。
- 保留完整宫墙、护城河、四座角楼和主要院落轮廓。三大殿、后三宫有明确的体量差异，太和殿作为最主要的视觉焦点。
- 红墙有厚度，门洞可辨认，殿堂有台基、台阶、柱廊和屋脊层次。院落铺石而非草坪；植物主要集中在真实有园林的区域。
- 午门按凹字形整体建模；太和殿采用重檐庑殿顶，中和殿采用四角攒尖顶。关键建筑分别制作模型配置，背景院落使用可复用建筑组件。依据：[午门](https://www.dpm.org.cn/explore/building/236454.html)、[太和殿](https://www.dpm.org.cn/building/talk/223525.html)、[中和殿](https://www.dpm.org.cn/explore/building/236464.html)。
- 首版提供晴日、夕照、瑞雪三种氛围。瑞雪主要落在屋顶、台基和庭院边缘，保持红墙、道路和建筑轮廓清晰；氛围选择表达艺术效果，不表达当日天气或开放时段。
- 总览只展示少量主要标签；缩放后再显露院落与建筑名。选择建筑时相机轻推近，标签避让，卡片沿用现有样式。
- 第二轮优先适配“积木宫城”，再考虑像素和纸艺。各风格共用同一地理布局与通行数据，逐个验收后再显示在选择器中。

## 空间与景点范围

首版覆盖整座宫城的外观与分区，重点制作中轴，东西两侧提供院落层次和少量探索分支。天安门、景山不纳入故宫内部游览路线。

| 区域 | 首版可点开的内容 | 建模重点 |
| --- | --- | --- |
| 南部入口 | 午门、太和门 | 凹字形城楼、内金水河与桥、入口广场 |
| 外朝 | 太和殿、中和殿、保和殿 | 三殿不同屋顶、台基、广场、侧廊 |
| 内廷 | 乾清宫、交泰殿、坤宁宫 | 递进院落、宫门与殿堂的尺寸关系 |
| 北部 | 御花园、神武门 | 古树、亭阁、假山和北部出口 |
| 东西分支 | 宁寿宫区、慈宁宫区 | 在正确方位形成可识别的独立院落组团 |

以上共 12 个内容入口。乾清门、内金水桥、东华门、宫墙与角楼等仍需出现在场景里；“有模型”与“独立内容入口”分开管理。入口不等于承诺建筑内部可进入。角楼先作为城外观察对象，避免把小人放到不可达的屋顶或墙顶。

中轴叙事顺序：午门 → 内金水桥与太和门区域 → 太和殿 → 中和殿 → 保和殿 → 乾清门 → 乾清宫 → 交泰殿 → 坤宁宫 → 御花园 → 神武门。此顺序表达空间与讲解关系，实际步行线路须通过已核验的通道绕行建筑。官方经典路线可参考[故宫主题导览资料](https://www.dpm.org.cn/Uploads/File/2022/06/16/u62aa8d7c77f91.pdf)。

## 游客交互

1. **进入景区。** 景区列表增加故宫，与西湖并列；地图页保留 2D/3D 切换、风格选择和返回景区入口。故宫拥有自己的游览位置、印章和氛围状态。
2. **自由走动。** 点击地面或使用方向键在庭院、道路与开放门洞内行走。点击殿堂时，角色前往指定观赏点，镜头展示殿堂；墙体和建筑实体阻挡行走。
3. **沿中轴游览。** 路线只高亮下一段，停靠后给出短讲解与“继续前往”；每次可跳过讲解或退出。全流程按演示节奏控制在数分钟，不把动画速度换算成真实参观时长。
4. **查看内容。** 建筑卡片提供实景照片、建筑故事和语音。资料不足的问题由导游说明缺少依据，讲解可追溯到对应资料；已验证世界模型的景点才出现相应入口。
5. **收集印章。** 首版设置午门、太和殿、乾清宫、御花园四枚探索印章，复用现有印章机制。第二轮可加“辨认三种屋顶”或“寻找屋脊小兽”等观察任务。
6. **观察建筑。** 小人在墙后或檐下时用轮廓提示；近景适当提高镜头。首版不做开屋顶展示室内，避免增加未核验内部布局。

官方参观规则为午门入、神武门或东华门出，不应把“四座城门”都当作游客入口。[官方参观说明](https://www.dpm.org.cn/subject_booking/)

开放状态与建筑是否显示分开：截至本次检索，官方存在太和门自 2026-08-03 起封闭施工的公告。建模可保留其建筑外观，路线需要采用后续核验的可通行通道；不能把中轴叙事顺序直接当成穿门路线。制作时重新检查公告并记录核验日期。[太和门施工公告](https://www.dpm.org.cn/announce_detail/379422.html)

## 图像与单点世界

- 真实照片从有明确可用许可的资料或合作方素材中选取，逐项保存来源与授权范围。故宫官方网站和全景服务用于事实与视觉核对，公开可见不等于图片可直接复制使用。
- 2D 绘卷、封面和风格参考适合使用 ImageGen。先有可信的空间结构，再生成视觉素材，并把图片上的位置与同一份景点坐标校准；文字标签在界面叠加。
- ImageGen 补视角按现有审核流程使用，记录推测范围。先核对屋顶、门洞、侧翼和院落，不能让补图改变建筑形制或虚构通道。
- 单景点世界候选为“太和殿前广场的局部观赏点”，以同一区域可授权、可对齐的多视角素材为前提。先进行素材评估再决定是否生成；范围聚焦一个局部空间。
- 大地图、讲解和实景照片构成首版完整游览闭环。世界模型通过后，再复用按方向切换下一景点的入口；切换是场景跳转，不宣称局部生成世界连续覆盖整座故宫。

## 框架改造设计

现有地图包、模型库、风格切换、详情卡、印章和世界模型入口可以复用。下表保留实施前的基线与改造目标；当前实现以制作与验收记录为准。

| 项目 | 当前实现 | 故宫改造 |
| --- | --- | --- |
| 景区内容注册 | `createWorkspace` 只内置西湖，已有工作区不会自动追加新种子 | 增加稳定 ID 为 `forbidden-city` 的内容种子，增量补入旧工作区，保留用户草稿和发布快照 |
| 地理与地面 | 以水岸、山体和展示性高度为主 | 增加平整院落、铺装、台基与台阶；水域表达真实护城河和内金水河 |
| 建筑组件 | 现有受控模型主要是亭、塔和桥 | 增加宫殿、城门、宫墙、侧廊、角楼和台基组件；关键地标使用独立组合模型 |
| 通行 | `walkable` 判断边界、水陆和地形，最短路是无向边 | 增加实体障碍、门洞、可走区域、边的方向及通行状态；点击直线捷径、寻路和键盘移动使用同一规则 |
| 尺度 | 多处参数针对西湖的大范围地图 | 统一坐标单位换算；按景区尺度配置相机、裁剪面、角色大小、步速、到达半径、阴影和空间采样精度 |
| 景观组件 | 池塘、荷花、城市、植被等被固定装配 | 组件按地图包启用，支持缺省和空集合；故宫宫殿区使用受控布景 |
| 界面与记忆 | 存在西湖专用文案；游览 session 使用同一个键 | 文案与氛围由景区配置提供；按景区隔离位置、氛围与风格，印章已有景区隔离可沿用 |
| 校验 | 默认西湖；要求所有景点两两互达 | 遍历所有注册地图，分别输出报告；有向路线改验入口到活动停靠点、停靠点到出口的可达性 |

不直接把新字段塞入 v1 文件。拟通过兼容 v1 的新版契约扩展，旧西湖包继续通过原有校验和运行。字段名在实施前通过最小样例确定，建议分工如下：

- `geography.json`：坐标、地理来源、建筑实体占地、院落与道路边界、门洞位置、基础路网。地理实体拥有稳定 ID。
- `layout.json`：模型实例引用地理实体 ID，定义建筑组件、细节、材质槽位与展示尺度。视觉模型与通行轮廓由共同实体生成，避免各画一份后错位。
- `style.json`：颜色、材质、屋顶表现、灯光与氛围；不改变建筑占地和通道关系。
- `interaction.json`：出生点、停靠点、推荐游览、入口与出口、通行方向、开放状态及核验来源、相机与探索规则。
- 内容种子：景点名称、照片、讲解、来源、2D 图钉和可选世界资产；与地图景点共用 ID。

地理编译器将静态实体与交互通行状态合并成一份可行走结果。建筑本体、临时闭门和“仅可观看”是不同信息，不用隐藏建筑来表达关闭，也不通过移动建筑来修通路线。

## 制作顺序与验收

1. **布局底稿。** 整理官方布局与可用地理资料，标出城墙、主殿、院落、门洞和候选观赏点；做午门—太和殿的小范围灰盒，验证尺度、穿门和绕行。
2. **主风格与主轴。** 制作午门、太和殿、中和殿等关键组件，确定红墙金顶的材质与光照；铺开宫城轮廓和中轴院落，再补背景建筑。
3. **内容闭环。** 注册故宫、补齐 12 个入口，打通新旧浏览器数据迁移、照片、讲解、路线与印章，完成晴日/夕照/瑞雪。
4. **视觉与路网验收。** 检查桌面/窄屏、俯视/近景、进门/转角/台阶、方向键连续移动以及西湖来回切换；审核开放通道和照片来源。
5. **扩展展示。** 主版本通过后适配积木宫城，再评估局部世界模型。每个扩展独立记录验证结果。

首版验收目标：

- 总览能辨认午门、中轴三大殿、后三宫、御花园与宫城边界；建筑轮廓和相对布局可与来源核对。
- 12 个内容入口可用；4 枚印章有清晰触发条件；主轴导览可开始、继续和退出。
- 寻路和手动移动都不穿墙、不横穿殿堂、不跨越护城河；门洞允许通过；关闭区域不被自动路线选中。
- 建筑仍可在总览中查看，现场开放状态与观赏信息表达一致。
- 返回西湖后原有五风格、游览和用户数据正常；两个景区的状态不串用。
- 性能目标为桌面稳定接近 60 fps、窄屏接近 30 fps，需在实际设备记录结果；重复瓦片、栏杆、柱廊等优先采用实例化和距离分级细节，未测量前不声称达到指标。
- 完成数据契约、空间验证、浏览器审图和人工布局核对；部署状态单独报告。

## 演示叙事

从西湖切换到故宫 → 展示完整皇家微缩沙盘 → 小人从午门穿过真实通道 → 太和殿前听一段讲解并收集印章 → 切换瑞雪 → 打开一个景点的实景资料。

技术讲解使用真实产物：输入资料与来源 → 地理/布景/风格/交互标准数据包 → 结构与空间校验 → 人工审图 → 同一地图引擎展示两个景区。代码、生成记录和验收报告支撑这一流程。
